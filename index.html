2. Simulator settings

Before the first hardware test, use an empty .py file, auto-indent enabled and auto-closing brackets/quotes disabled in VS Code. Don't use an editor with suggested code completion until calibrated.

Run simulation to validate the proposed keystrokes.
Why Home → Shift+End → Delete?

After Enter, VS Code may add spaces. On a whitespace-only line, Home should move to column zero; Shift+End selects its whitespace; Delete removes it. The ESP32 then types the exact indentation from your source. No knowledge of block nesting is required. Some editors handle these keys differently, so we must verify in real VS Code.

5. Real-world test checklist

  1. Back up your current firmware and GitHub Pages website. Upload the new firmware first.
  2. Connect Windows first as the BLE keyboard, then connect Android through this website.
  3. Open a blank Python file in VS Code and click inside it. Use the recommended editor settings in README.
  4. Send the sample in Smart Python mode. Wait for READY:P, then press BOOT.
  5. Compare actual VS Code text with original. If different, report the first mismatching line and keep the baseline 40/40 ms firmware timing.

The site verifies instruction bytes with CRC32 and simulates editor behaviour. It cannot verify that Windows inserted every keystroke. Test on your own devices only.
